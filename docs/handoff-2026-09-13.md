## Things that will bite you if you don't know them

**The Stripe CLI will not install via npm on this machine.** `npm i -g @stripe/cli` fails with
*"unsupported platform win32-arm64"*. That is the npm wrapper's own platform allowlist, **not** a real
incompatibility — Stripe ships `stripe_<version>_windows_x86_64.zip` and Windows on ARM runs it under
emulation, which is what `winget install Stripe.StripeCli` fetches. The npm package also leaves a
non-working `stripe` on `PATH`, so `command -v stripe` succeeds while `stripe --version` errors.
**Check the second, not the first.** Clean it up with `npm uninstall -g @stripe/cli`.

**`npm install stripe` triggers the npm 10/11 lockfile procedure in full.** This is Task 1 of the plan
and it is a task on its own for a reason: getting it wrong fails the Cloudflare build during
dependency install, with an error that points nowhere near this repo. Regenerate **after the last
install**, and verify `npm ci --dry-run` under both npm versions.

**The Stripe SDK needs `Stripe.createFetchHttpClient()` on workerd.** The default HTTP client reaches
for Node's `http`, which does not exist on Cloudflare's runtime — so the default passes `npm run dev`
and `npm run build`, and fails only under `npm run cf:preview`. Task 7 exists to catch this.

**Shell scripts need LF endings.** `core.autocrlf=true` here, so a committed `.sh` picks up a `\r` on
its shebang and bash reports *"No such file or directory"* — naming the script rather than the cause.
`.gitattributes` now pins `*.sh text eol=lf`; that came from hitting it live.
