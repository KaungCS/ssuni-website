## Two things were broken before a line of code was written

**The Supabase project had paused itself.** `supabase projects list` reported `status: INACTIVE`, and

looks like anything except a billing tier. Free-tier projects auto-pause after 7 days without

the CLI has no unpause command.

This is now [ADR 0012](adr/0012-supabase-free-tier-through-launch.md) and issue
[#44](https://github.com/KaungCS/ssuni-website/issues/44). **Staying on the free tier was a decision,
not an oversight** — Pro is not affordable yet — and #44 is the mitigation: a `pg_dump` on a 3-day
cron that backs up *and* keeps the project awake, deliberately as one job so its failure is loud.
**Until #44 lands, the only thing preventing another pause is the cadence of development itself.**

**The Cloudflare Workers build was failing, and the first diagnosis of it was wrong.** Recording both
the wrong answer and the right one, because the wrong one was confidently argued and looked solid.

*The wrong diagnosis* was "the API token has been rotated", resting on two bad inferences. First,
that both failures took **zero seconds** (`started_at` == `completed_at`) so the build never ran —
**Cloudflare's check-runs always report those two timestamps identically**, so the duration carries
no information whatsoever. Second, that PR #43 was "a single markdown file" and so could not fail a
build — but #43 was branched off `feat/catalog-filter-drawer`, not `main`, so it carried that entire
branch. Checking a *commit's* stat instead of the branch's diff against `main` is what produced that.

**Do not read meaning into Workers Builds timestamps. Read the build log.** The log is on the
Cloudflare dashboard and is the only thing that says what happened.

*The real cause* was the npm 10 / npm 11 lockfile divergence `CLAUDE.md` already documents,
reintroduced by regenerating the lockfile with npm 10 **in the middle** of the session and then
running two more npm 11 installs afterwards. The lockfile went from 9 `@emnapi` entries to 5, and the
remote died at `npm clean-install` with *"Missing: `@emnapi/runtime@1.11.3` from lock file"* before
reaching any app code.

Fixing it turned up three things now written into `CLAUDE.md`:

- **`npx npm@10.9.2 install --package-lock-only` crashes** with `Cannot read properties of null
  (reading 'edgesOut')` whenever a `package-lock.json` already exists. Reproduced under Node 24 and a
  clean Node 22 (npm 10.9.3), with and without `node_modules`. **The recipe needs `rm
  package-lock.json` first**, and the version in `CLAUDE.md` before today did not.
- **This machine is `arm64`** — Windows on ARM — while Cloudflare builds on **x64 Linux**. That
  mismatch in which optional native binaries get resolved is the root of this whole class of failure,
  and it is the same reason an unsigned ARM64 `@ast-grep/napi` once tripped Application Control.
- **Vitest is pinned to 3.x deliberately.** Vitest 4 pulls vite 8, and with it `rolldown` and
  `esbuild@0.28`, whose optional per-platform binary sets npm 10 and npm 11 resolve *differently* —
  which breaks the shared lockfile outright. A lockfile npm 10 resolves from scratch is rejected by
  npm 11; the reverse is also true; and merging the two is rejected by both. Vitest 3 pulls no
  rolldown at all and restores the invariant. **Do not upgrade to vitest 4** without re-verifying
  `npm ci --dry-run` under both npm versions.

**The token was never the problem** — `main` built green at 04:41 on 2026-09-09.

**Still unresolved at the end of the session.** With the lockfile fixed the remote got *much*

## Things that will bite you if you don't know them

**Vitest is here now, and it is deliberately small.** `node` environment by default; exactly one file
opts into jsdom via a `@vitest-environment` docblock. That is not laziness — issue #32 exempts
presentational components, and a global DOM environment invites the tests this project decided not to
write. **#15 and #18/#30 extend this suite rather than starting their own.**

**Vitest 3, not 4 or 5** — see the lockfile section above; this is a hard constraint, not a preference.
Separately, and not fixed: the repo pins `@types/node@^20` while Kaung runs Node 24, with no `.nvmrc` or `engines`
anywhere. Pre-existing, latent, and worth an issue eventually — not worth touching three weeks out.

**Money is summed in integer cents.** `19.99 * 3` is `59.97000000000001`. A test holds this line.
Anything that computes money — #15 especially — must not reintroduce decimal arithmetic.

**The subtotal is computed in exactly one place** (`reconcile` in `lib/cart.ts`). If `/cart` and
checkout ever disagree about a price, this is why. Do not add a second implementation in a component.

**`useSyncExternalStore`, not load-effect-plus-save-effect.** The obvious two-effect shape writes `[]`
over the shopper's stored Cart on mount. **The end state recovers**, which is the trap: the first test
written for it passed against the bug. The damage is the transient write, which another tab or a
reload landing in that window reads and keeps. The shipped test records every write and requires none
be empty.

**Three bugs came only from driving the real app**, and no unit test could have caught them: a
non-UUID variant id returning **HTTP 500** from Postgres's uuid cast; a mobile layout pushing the line
price past the page padding because a flex child lacked `min-w-0` (`body.scrollWidth` did *not* catch
this — the screenshot did); and the nav badge reading 99 while the line read 5. **Take screenshots.
The 2026-08-31 handoff says the same thing and it was right again.**

**The dev-server and workerd orphans are real, again.** Stopping the task left `node` holding 3000.
Worse on the workerd side: killing the `workerd` child was useless, because the **`wrangler ... dev`
node parent respawns it** — the port kept coming back with a new PID each time. Kill the parent with
`taskkill //PID <parent> //T //F`. Find it with `Get-CimInstance Win32_Process`. Always confirm both
ports are free before starting a build.

**The Playwright MCP browser does not work on this machine** — it is pinned to real Chrome, and
installing Chrome needs Administrator. `npx playwright install chromium` works, but the MCP server
will not use it. The way through is a scratch script importing `playwright` directly, with the package
installed **in the scratchpad**, not the project. Also: `waitUntil: "networkidle"` never settles
against `wrangler dev` — use `domcontentloaded`.

**A third Product appeared in the catalog** (`og-cool-cap`) since 2026-08-31. The client is adding
rows between sessions, exactly as `CLAUDE.md` warns. Nothing broke, because no test asserts a count.
Keep it that way.
