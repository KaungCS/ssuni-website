## Things that will bite you if you don't know them

**`auth.users` is in the `auth` schema, not `public`.** Studio's Table Editor opens on `public` and
will not list it, so it looks as though the users table is missing. Authentication → Users, or the
schema dropdown. Cost real confusion this session; now documented in CLAUDE.md (on the branch).

**There is no UI for granting admin, deliberately.** `public.admins` is SELECT-only from the browser
and has no write grant, so the dashboard can never add admins to itself. Grant one in the SQL Editor,
looking the id up by email rather than typing a uuid:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'someone@example.com'
on conflict do nothing;
```

Keep it keyed on the uuid: `user_id` is a foreign key so a typo is rejected rather than producing a
row matching nobody, email is mutable in Supabase Auth, and `auth.uid()` returns the uuid so an
email-keyed policy would need a join into `auth.users` in every evaluation.

**A green test can prove nothing.** The allowlist-enumeration check in `admin-path.sql` originally
seeded a second admin by selecting another `auth.users` row — but this project has exactly **one**
user, so it inserted nothing and `count(*) <= 1` passed against a one-row table. A `using (true)`
policy would have passed it too. It now creates a throwaway user inside the rolled-back transaction,
plus check 38 asserting there really are two rows to enumerate before check 40 claims anything.
Watch for this shape: a negative assertion whose setup silently did nothing.

**`next/image` is safe on workerd, and it was checked rather than assumed.**
`@opennextjs/cloudflare`'s `/_next/image` handler serves the original image when no `IMAGES` binding
exists, and gates remote hosts on `hasRemoteMatch(__IMAGES_REMOTE_PATTERNS__, url)`. So
`next.config.ts`'s `remotePatterns` is load-bearing — and it is matched by **wildcard host rather
than derived from `NEXT_PUBLIC_SUPABASE_URL`**, because that is a Cloudflare *build* variable and
deriving it would mean an unset variable silently 400s every product photo.

**The dashboard adds no RLS bypass.** Nothing in `app/admin/` or `lib/admin*.ts` imports
`lib/supabase/admin.ts`, and nothing should. CLAUDE.md predicted `/admin/orders` would be the third
caller; it is not, because `orders_admin_all` plus a column-scoped
`grant update (status, tracking_link)` already said exactly the right thing. That pattern held for
every table — the write policies had existed since August and had simply never been consumed, which
is what made lifting ADR 0007's deferral affordable at all.

be obtained without Kaung's inbox. What *is* proven: the gate's three branches are unit-tested and
mutation-checked, `admin-path.sql` proves the admin write policies against the real database, and

a gallery. `lib/catalog.ts` reaches `next/headers`, so testing it means mocking or widening the
module's API for a test. The RLS suite proves `sort_order` round-trips through PostgREST; the JS
re-sort of that data is uncovered. Not on the money path.

**CLAUDE.md has a stale claim that was found and deliberately left.** It says `variants_available`
"ends in `where not p.is_hidden`". It does not — `20260825130000` rebuilt it as `security_invoker`
and RLS does the filtering. The conclusion is right for an anonymous shopper but the mechanism is
wrong, and the difference matters: RLS is what lets a signed-in admin still see Hidden Variants.
It appears in the `lib/cart.ts` and `lib/catalog.ts` bullets. Worth fixing next session.
