## Two decisions that contradict the #37 issue text

The issue was written on 2026-08-30 and was not edited after the 2026-08-31 grilling. **Read the PR
description, not the issue, for what was actually built.**

- **There is no "Featured" sort.** #37 defined Featured as the existing `created_at desc` — which is
  precisely what Newest is, so the menu would have carried two labels for one ordering. The sort menu
  is Newest / Price low→high / Price high→low. Do not re-add Featured from the issue text. If a
  merchandised top-of-catalog is ever wanted, it is a `featured_rank` column, not a Collection doing
  double duty as a sort — Collections are filters (`CONTEXT.md`).
- **The Apply button does not name a result count.** The issue's "Show N pieces" idea was dropped:
  nothing recomputes N as boxes are ticked, so the button would describe the view the shopper is
  leaving.

## Things that will bite you if you don't know them

**`lib/catalog.ts` can never be imported by a client component.** It reaches `next/headers` through
`lib/supabase/server.ts`, so a `"use client"` file importing *any runtime value* from it fails the
build with "You're importing a module that depends on next/headers". Type-only imports are erased and
are fine; one value import is not. This is why `lib/catalog-url.ts` exists — the pure half (filter and
sort vocabulary, parsing, `catalogUrlKey`) lives there and imports nothing but `lib/taxonomy.ts`.
`lib/catalog.ts` re-exports all of it, so server-side callers still see one door. **Client components
import `@/lib/catalog-url`.** This cost a debugging cycle in-session; the split is the fix.

**`catalog_facets` takes `security_invoker = true` — the opposite of `variants_available`, on
purpose.** `variants_available`, two migrations earlier, has a long comment insisting on definer
rights because it reads `reservations`, which anon cannot, and invoker rights there would report full
stock as available and oversell. `catalog_facets` reads only `products`, so invoker rights let RLS
drop a Hidden Product's terms for free instead of the view re-implementing the Hidden rule. Both
migrations now carry comment blocks saying this. **Do not "fix" the inconsistency** — it is the one
place in the schema where the same-looking question has opposite right answers.

**A GET form replaces the entire query string.** Every param the drawer does not render a field for
is dropped the moment a shopper presses Apply. That is why New Arrivals has a visible checkbox rather
than a hidden input. **Any new catalog URL param needs a field in the drawer**, or arriving at a URL
carrying it and pressing Apply silently discards it. Relevant to #38 and to anything that adds a
filter dimension later. There is a browser check covering exactly this.

**The drawer's form is keyed on the current search params.** Remove the key and ticks abandoned by
closing the drawer without applying survive into the next open — nothing unmounts, so the browser
keeps them.

**Behavioural checks do not see layout.** A first pass at the fieldset rules used a floated
`<legend>`, which threw the first option of every group to the right edge and dropped its label. All
27 browser checks still passed. The screenshot caught it. Take a screenshot when changing this
component, don't trust green assertions alone.

**`npm run cf:preview` failed once with "An Application Control policy has blocked this file"** on an
unsigned ARM64 native module (`@ast-grep/napi`, reached through `@opennextjs/cloudflare`). It failed
before reading a single line of project source, and **succeeded on a plain retry**. If it recurs it
will look exactly like a build bug in whatever you last edited, and it is not one. Retry first.

**The dev-server orphan in `CLAUDE.md` is real — confirmed this session.** Stopping the `npm run dev`
task left a `node` process still listening on 3000 and it had to be killed by PID. The same happened
with `cf:preview`: killing workerd was not enough, wrangler respawned it, and the parent `node` had to
go. Always confirm the port is actually free before starting a build.

**The facet assertions in `supabase/tests/rls.mjs` compute their target at runtime**, deliberately.
They ask "which of the hoodie's terms does no other visible Product carry" rather than hardcoding
`hoodies`, so a Product appearing between sessions cannot break them — the failure mode that broke six
exact-count assertions on 2026-08-30. Extend them the same way.

**The browser verification was a scratch script and is not committed.** It ran 27 checks against
`next dev` and again against workerd. Its coverage is itemised in the PR #42 description. There is
still no committed test runner — per `CLAUDE.md`, Vitest arrives with #12, and a browser harness
belongs to **#25** (Launch QA) rather than being smuggled in here.

## Where to start

**#38, taxonomy tables** — Kaung asked for this immediately after the drawer and asked that it not
drift. It removes the ADR 0011 duplication: the vocabulary currently lives in `lib/taxonomy.ts` *and*
in CHECK constraints in `20260830120000_taxonomy_declared_values.sql`, and the two must be edited
together or a term added to one and not the other fails in opposite directions.

Two things #38 should know about what just landed:

- **`catalog_facets` gets re-pointed at the new tables.** `getCatalogFacets()` is the seam, and the
  drawer consumes only its return shape — neither `components/CatalogFilterDrawer.tsx` nor
  `app/catalog/page.tsx` should need touching. If they do, the seam was drawn in the wrong place.
- **`getCatalogFacets()` orders each list by the declaration order** in `DEPARTMENT_SLUGS` /
  `CATEGORY_SLUGS` / `COLLECTION_SLUGS`, not alphabetically, so the drawer reads in the same sequence
  as the mega menu. Real tables will need an explicit sort column to preserve that; database order is
  not a substitute.

After #38, the agreed order is **#11** (Product images to Supabase Storage), which is gated on the
client delivering real photography (#5).

**#9 looks complete and is still open.** `data/products.json` is gone, both catalog routes are server
components reading Supabase, and `app/catalog/[slug]/page.tsx` calls `notFound()` — which also closes
out the "unknown slug returns HTTP 200" defect the 2026-08-24 handoff raised. Worth a look and a close
rather than a task.

**Still the highest-value non-code items**, unchanged and able to hold the launch date with every line
